# HyPrism.Desktop

`HyPrism.Desktop` является активным хостом приложения

## Состав

- `App.axaml` подключает общие токены, стили и ресурсы
- `Shell` содержит главное окно, нативное управление окном, навигацию, состояние верхнего уровня и синхронизированный с кадрами переход стартового экрана загрузки
- `Features/Dashboard` содержит домашнюю страницу и модель представления экземпляров
- `SettingsViewModel` адаптирует `IDesktopSettingsStore` для интерфейса настроек
- `DesktopSettingsStore` владеет настройками Avalonia и сохраняет их через хранилище конфигурации Core
- `ExternalUriLauncher` открывает ссылки в системном браузере и сохраняет абсолютный экранированный URI при передаче OAuth-запросов операционной системе
- `FilePicker` использует нативный `StorageProvider` Avalonia вместо запуска системных утилит
- `SystemMemoryProvider` предоставляет объем памяти для настроек Java
- `GpuProvider` реализует контракт определения GPU из Core через инструменты платформы хоста
- `Features/News` получает официальные новости Hytale и хранит кеш ленты и статей в `Cache/News`
- `Features/About` предоставляет данные репозитория, контрибьюторов, коммиты и аватары для страницы «О программе»
- `Features/Settings` владеет адаптивным интерфейсом настроек и параметрами Desktop
- `Features/Profiles` владеет адаптивными карточками, содержимым и wizard профилей в стиле экземпляров и передает порядок, хранение, переключение и сохранение сессий сервисам аккаунтов Core
- `Controls/WizardHost` управляет жизненным циклом wizard, нормализацией активного шага, запуском reveal-анимации, отложенной очисткой и боковой панелью для экземпляров, профилей и источников загрузки
- `Controls/WizardScreenTransition` реализует низкоуровневые фазовые переходы между обзором и wizard, а также между шагами, включая синхронизированную с рендерингом анимацию, восстановление активного шага после прерывания и отслеживание якоря только в открытом wizard
- `Controls/WizardRevealIcon` предоставляет общий якорь, слой движения и Lottie-плеер, поэтому reveal-иконки стабильно загружаются и не анимируют позицию при открытии или закрытии wizard
- `Controls/AdaptiveMasterDetailHost` управляет общим состоянием широкого и компактного master-detail лейаута, брейкпоинтом, колонками, шириной контента и сохранением намерения открыть детали, оставляя синхронизацию лейаута мгновенной, а пользовательскую навигацию анимированной
- `Controls/ReorderableListController` управляет захватом указателя, drag preview и вычислением позиции сброса для списков профилей и экземпляров
- `Platform` содержит нативные адаптеры URI, файлового пикера, памяти и GPU, а также общий постоянный кеш удаленных изображений
- `Integrations/Discord` реализует presence-порт Core и следует жизненному циклу Avalonia-хоста
- пользовательские контролы отвечают за rich content новостей, плавный скролл, анимированные комбобоксы и переиспользуемые плавно исчезающие popup
- `.resx`-файлы в `Localization` содержат строки интерфейса для поддерживаемых культур

## База UI

Переиспользуемое оформление Desktop разделено на два слоя:

- `Styles/Tokens.axaml` определяет цвета поверхностей, текста, интерактивных состояний, выбора в навигации, семантических статусов, свитчей и всплывающих элементов
- `Styles/Controls.axaml` определяет общие анимированные ComboBox, поверхность popup, элементы ComboBox, свитчи, `SettingsRow`, действия wizard и сегментные переключатели

Страницы подключают переиспользуемые контролы через классы `uiComboBox`, `uiPopupSurface`, `uiToggle`, `uiSettingsGroup`, `uiSettingsRow` и `uiSegmentedControl`. Активные кнопки, селекторы, свитчи и слайдеры получают общий курсор руки, а ввод текста и изменение размера сохраняют специализированные курсоры. `FadingPopup` управляет открытием, закрытием по клику вне элемента и клавиатуре, таймингами анимации и удержанием при закрытии для списков ComboBox и меню функций. Новые цвета интеракций и тайминги анимаций должны добавляться в эту базу, а не в стили отдельной функции

`MotionDurations` задает общие тайминги анимаций по назначению. `RotatingVisual.IsActive` предоставляет единое синхронизированное с рендерингом поведение спиннера, которое запускается и останавливается через binding вместо таймеров отдельной функции

В Desktop по умолчанию включены compiled bindings. View model предоставляет состояние и команды, а code-behind используется только для поведения, зависящего от ввода, лейаута или анимаций Avalonia

Внешние ссылки и файловые диалоги остаются в Desktop. Показ URI передается в Core как асинхронный callback только для интерактивного OAuth, а выбор файлов используется непосредственно view model проекта Desktop. Desktop также реализует `IOAuthCallbackPageRenderer` со встроенным логотипом HyPrism, цветами лаунчера, адаптивной компоновкой, статусом результата и подсказкой о закрытии окна, локализованными по текущему значению `IDesktopSettingsStore.Language`

Модели новостей и ответов GitHub находятся рядом с функциональностью Desktop, потому что это данные представления, а не часть логики игры или аккаунтов
