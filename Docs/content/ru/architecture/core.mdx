# HyPrism.Core

`HyPrism.Core` владеет поведением, которое не должно зависеть от UI-фреймворка

## Приложение и инфраструктура

- `Application/Composition` создает стандартный граф зависимостей
- `Application/Progress` публикует троттлируемые события прогресса загрузки и ошибок, привязанные к операции экземпляра; смена этапа и завершение проходят всегда
- `Application/Ports` содержит только возможности хоста, например Discord presence и определение GPU
- `Infrastructure` содержит JSON-хранилище конфигурации, логи и общие утилиты лаунчера
- `Integrations/Hytale` содержит детали протокола для официальных endpoint Hytale

## Игра

- `Game/Versions` получает метаданные версий из официального источника и зеркал
- `Game/Download` загружает файлы, применяет патчи и сообщает прогресс
- `Game/Instances` управляет метаданными, путями, выбором, импортом, удалением и миграциями экземпляров и поднимает `InstancesChanged` при любом изменении набора, чтобы хосты подписывались вместо опроса
- `Game/Launch` подготавливает Java, перенаправление endpoint клиента, DualAuth Agent, окружение и игровой процесс. Загрузка runtime и ожидание установщика учитывают отмену операции, а официальные архивы JRE с опубликованным SHA-256 проверяются до распаковки. Не прошедший проверку архив удаляется на каждой поддерживаемой платформе. Трекер процессов поднимает типизированные события старта и выхода с идентификатором экземпляра и кодом выхода, сверяет процессы, завершившиеся пока лаунчер был закрыт, а координатор запуска поднимает `LaunchFailed`, когда попытка завершилась без запущенного процесса
- `Game/Authentication` получает сетевые игровые сессии или выпускает self-contained токены OmniAuth через Local Node
- `HyPrism.LocalNode` хостит автономные session, account, каталог установленной косметики, configuration и empty-state social API
- `Game/Assets` управляет данными аватаров, нужными профилям и запуску игры
- `Game/Mods` ищет и устанавливает моды CurseForge или локальные файлы
- `Game/Patching` содержит клиент Butler для дифференциальных обновлений
- `Game/Sources` реализует официальный источник, JSON-зеркала, обнаружение зеркал и их безопасное сохранение

## Аккаунты

`Accounts` разделен на авторизацию, профили, личность и скины. Контракты находятся рядом со своей реализацией, а не собираются в отдельной папке абстракций

Репозиторий профилей и менеджер профилей поднимают `ProfilesChanged` после создания, удаления, переключения, изменения порядка и редактирования профилей, поэтому хосты реагируют на изменения через события, а не обновляют список вручную. При выходе игрового процесса репозиторий профилей накапливает общее время и счетчики по экземплярам, которые используются для определения самого популярного экземпляра профиля

## Правило зависимостей

Core может предоставлять возможности хоста через интерфейсы, но не должен ссылаться на Avalonia или модели представления

OAuth остается независимым от UI: Core формирует URI авторизации и принимает callback хоста для его показа. Открытием браузера владеет активный хост приложения. `IOAuthCallbackPageRenderer` позволяет хосту оформить локальный ответ callback без добавления ресурсов представления или зависимостей Avalonia в Core

Core получает путь каталога профиля, но не открывает системный файловый менеджер. Нативные файловые диалоги и определение объема памяти принадлежат `HyPrism.Desktop`

Запуск игры зависит только от `IGpuProvider` и `GpuAdapterInfo`. Конкретная реализация поиска адаптеров принадлежит каждому хосту

Парсинг новостей, данные GitHub и адаптер Discord Rich Presence принадлежат `HyPrism.Desktop`. Core использует только `IDiscordPresence` как возможность хоста при отправке состояния лаунчера и игры

## Local Node

`HyPrism.Desktop` владеет контроллером процесса `LocalNodeHost` через Core-контракт `ILocalNodeService`. Автономный запуск поднимает отдельный executable `HyPrism.LocalNode` до патча клиента, а затем передает владение lifetime PID игры через loopback control plane

Хост слушает только `https://h.localhost:8443`. Endpoint длиной 16 символов позволяет `ClientPatcher` направить session, account-data, telemetry, live-config, social, server-discovery и socket-gateway префиксы к одному loopback authority без изменения длины встроенного сегмента домена

Ключи подписи OmniAuth живут только в отдельном процессе ноды, привязанном к активной игре. Исходный identity handoff содержит приватный Ed25519 JWK, нужный DualAuth, а JWKS, authorization grant и access token отдают только публичный ключ. Данные аккаунта, скинов и настроек presence сохраняются в каталоге данных приложения

Вспомогательный процесс очищает провайдеры логирования ASP.NET и пишет собственный ограниченный по размеру файловый лог в текущий каталог запуска `Logs/<время-запуска>/`. Закрытие Desktop освобождает только process handles лаунчера, а нода продолжает следить за игрой и писать в этот каталог сессии до выхода игрового процесса
