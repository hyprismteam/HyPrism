# Данные и кеш

HyPrism отделяет постоянное состояние от данных, которые можно получить заново

| Расположение | Содержимое | Можно удалить |
| --- | --- | --- |
| `Config.json` | настройки и выбранные идентификаторы | нет, если сброс не нужен |
| `Profiles/Profiles.json` | полный список профилей и данные личности | нет |
| `Profiles/<profile-id>/` | файлы `Profile.json`, `HytaleSession.json`, `Skin.json`, аватары и данные сессии конкретного профиля | нет |
| `Instances/Instances.json` | реестр экземпляров и порядок отображения | нет |
| `Instances/<instance-id>/Meta.json` | идентификатор, ветка, версия и игровое время экземпляра | нет |
| `Mirrors/` | метаданные пользовательских зеркал | только если зеркала больше не нужны |
| `Runtime/GameProcesses.json` | реестр запущенных игровых процессов для восстановления после перезапуска лаунчера | да, когда HyPrism и все игровые сессии закрыты |
| `Cache/News/Feed.json` и `Article-<hash>.json` | разобранная лента и статьи | да |
| `Cache/Game/Versions.json` и `Patches.json` | снимки версий и патчей | да |
| `Cache/Game/Downloads/` | возобновляемые загрузки игры, включая незаконченные файлы `.part` | да, если загрузка или обновление не выполняется |
| `Cache/Images/News/` | закодированные превью и изображения статей | да |
| `Cache/Images/Github/` | закодированные аватары команды и контрибьюторов | да |
| `Logs/` | диагностика лаунчера, игровых экземпляров и Local Node по запускам | да, когда HyPrism и связанные игровые сессии закрыты |

В `Config.json` для выбора профиля хранится только `SelectedProfileId`. Старые поля личности читаются одноразовой миграцией и не представлены в модели конфигурации приложения

Имена JSON-файлов и свойства JSON-объектов, которыми владеет HyPrism, используют PascalCase. При первом обращении существующие файлы со старыми именами в нижнем регистре, kebab-case или snake_case переносятся в канонические имена, а чтение свойств остается нечувствительным к регистру. Внешние ответы сервисов, игровые файлы, кеши с именами на основе идентификаторов и обменный суффикс `.mirror.json` сохраняют нейминг своих контрактов

При запуске HyPrism переносит старые PWR-файлы из корня `Cache/` в `Cache/Game/Downloads/`, а `Cache/RemoteImages/` мигрирует в каталоги `Cache/Images/News/` и `Cache/Images/Github/` с заглавными буквами

## Логи сессии

При каждом запуске HyPrism создает `Logs/<yyyy-MM-dd_HH-mm-ss.fff>/` внутри каталога данных приложения. В этой папке собирается вся диагностика процесса лаунчера и запущенных им игровых сессий

| Файл | Содержимое |
| --- | --- |
| `launcher.log` | сервисы лаунчера, авторизация, загрузки, патчинг и управление процессами |
| `instance-<instance-id>.log` | полный стандартный вывод и поток ошибок одного игрового экземпляра |
| `local-node-<port>.log` | lifecycle, статусы маршрутов, время и ошибки автономного процесса Local Node |
| `local-node-requests-<port>.ndjson` | метаданные неизвестных запросов Local Node без заголовков, значений и тел |

Суффикс порта разделяет одновременно работающие процессы Local Node. После закрытия окна HyPrism нода может продолжить запись в исходную папку запуска, пока не завершится привязанная игра
