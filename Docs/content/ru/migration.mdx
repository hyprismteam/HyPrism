# Состояние миграции

Avalonia служит единственным UI лаунчера. Старый хост Electron.NET, React-фронтенд и генератор IPC удалены

## Текущая реализация

Экземпляры, профили, поиск и установка модов, новости и настройки используют нативные представления Avalonia. Desktop напрямую вызывает интерфейсы Core; Local Node запускается отдельным процессом для автономных сессий

Ответственность проектов описана в [обзоре архитектуры](/docs/architecture/overview), точки входа релиза в [упаковке](/docs/development/packaging)

## Незавершенные функции

UI первоначального знакомства и просмотр логов экземпляра не реализованы. Игрок создает профиль и экземпляр вручную по [первому запуску](/docs/getting-started/first-run), а диагностические файлы открывает в [каталоге данных](/docs/architecture/data-and-cache)

Видимое поле настроек может сохранять старое предпочтение до реализации соответствующей нативной функции. При описании поведения проверяйте потребителей поля

## Существующие данные

Сохраняется совместимость со старыми каталогами профилей, экземпляров, конфигурации и кэша. `CoreMigrationRunner` применяет эти миграции до создания моделей представления Desktop, читающих данные игрока. Завершенные постоянные шаги сохраняются в `MigrationState.json`, а обогащение названий версий повторяется при появлении данных источника

Миграции располагаются в `Sources/HyPrism.Core/Migrations/` и требуют тестов на фикстурах. Хосты могут запускать runner, но не должны содержать правила миграции

Для новой работы не возвращайте удаленный веб-мост. Историческая реализация доступна в системе контроля версий для изучения старых данных
