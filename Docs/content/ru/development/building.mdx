# Сборка

## Требования

- .NET 10 SDK
- Git
- Node.js 22 и pnpm только для документации

## Нативный лаунчер

```bash
dotnet restore HyPrism.sln
dotnet build Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
dotnet run --project Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
```

## Все solution-проекты

```bash
dotnet build HyPrism.sln
```

Solution содержит `HyPrism.Core`, `HyPrism.Desktop`, `HyPrism.LocalNode` и их тестовые проекты

## Локальная публикация

Платформенным entry point публикации служит `Scripts/publish.sh`. В Linux он создаёт `deb`, `rpm`, AppImage, Flatpak bundle и `tar.xz` из одного self-contained результата Desktop. Сначала установите `rpm`, Flatpak, Flatpak Builder и appimagetool, затем выполните:

```bash
./Scripts/publish.sh all --version 1.2.3 --output dist
```

Для Linux одного формата используйте `deb`, `rpm`, `appimage`, `flatpak` или `tar`. В macOS команда `./Scripts/publish.sh dmg` создаёт DMG. В Windows выполните `bash Scripts/publish.sh all` через Git Bash, чтобы создать ZIP, MSI и EXE-инсталлятор. Все platform-workflow вызывают этот dispatcher

## GitHub Actions

`.github/workflows/ci.yml` является точкой входа для push и pull request. Он вызывает независимый workflow тестов и диспетчер сборки. `.github/workflows/build.yml` только выбирает платформы, а `build-linux.yml`, `build-windows.yml` и `build-macos.yml` отвечают за упаковку своих платформ

Сейчас CI создает `deb`, `rpm`, AppImage, Flatpak bundle и `tar.xz` для Linux x64, портативный ZIP, MSI и EXE-инсталлятор для Windows x64 и DMG для macOS ARM64. Release-сборки повторно используют те же platform-workflow и передают версию релиза в имена артефактов

## macOS-пакет

macOS workflow публикует self-contained Desktop для `osx-arm64` с apphost Local Node рядом, собирает нативный bundle `.app`, применяет ad hoc-подпись, проверяет bundle и создает загружаемый DMG
