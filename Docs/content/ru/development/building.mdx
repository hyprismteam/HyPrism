# Сборка

## Требования

- .NET 10 SDK
- Git
- Node.js 22 и pnpm только для документации

## Нативный лаунчер

```bash
dotnet restore HyPrism.sln
dotnet build Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
dotnet run --project Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
```

## Все solution-проекты

```bash
dotnet build HyPrism.sln
```

Solution содержит `HyPrism.Core`, `HyPrism.Desktop`, `HyPrism.LocalNode` и их тестовые проекты

## Локальная публикация

Entry point публикации и платформенные assets централизованы в `Packaging/`. В Linux publisher создаёт `deb`, `rpm`, AppImage, Flatpak bundle и `tar.xz` из одного self-contained результата Desktop. Сначала установите `rpm`, Flatpak, Flatpak Builder и appimagetool, затем выполните:

```bash
./Packaging/publish-linux.sh all --output dist
```

Для Linux одного формата используйте `deb`, `rpm`, `appimage`, `flatpak` или `tar`. В macOS команда `./Packaging/publish-macos.sh dmg` создаёт DMG. В Windows команда `pwsh Packaging/publish-windows.ps1 all` создаёт ZIP, MSI и EXE-инсталлятор. Каждый platform-workflow напрямую вызывает соответствующий entry point

Windows publisher проверяет наличие `HyPrism.Desktop.exe` и `HyPrism.LocalNode.exe` перед созданием portable-архива и инсталляторов. Он устанавливает закрепленную версию WiX 6 в отдельный временный каталог и использует соответствующую версию bootstrapper-расширения

Единственным источником версии релиза служит свойство `Version` в `Sources/HyPrism.Desktop/HyPrism.Desktop.csproj`. Packaging-скрипты получают вычисленное значение через MSBuild и используют его для assembly metadata, package metadata и имён артефактов. Release-тег должен совпадать с `v<Version>`, иначе release-workflow завершится ошибкой

## GitHub Actions

`.github/workflows/ci.yml` является точкой входа для push и pull request. Он показывает отдельные группы checks для Core, Desktop, Local Node и Packaging. Каждая тестовая группа вызывает свой reusable matrix workflow, а Packaging использует диспетчер сборки. `.github/workflows/build.yml` только выбирает платформы, а `build-linux.yml`, `build-windows.yml` и `build-macos.yml` отвечают за упаковку своих платформ

Сейчас CI создает `deb`, `rpm`, AppImage, Flatpak bundle и `tar.xz` для Linux x64, портативный ZIP, MSI и EXE-инсталлятор для Windows x64 и DMG для macOS ARM64. Release-сборки повторно используют те же platform-workflow и передают версию релиза в имена артефактов

Linux workflow повторяет установку runtime из Flathub при временной ошибке загрузки metadata или пакетов. Последняя неудачная попытка по-прежнему останавливает сборку до начала упаковки. Экспорт Flatpak и создание bundle используют одну ветку `stable`, заданную Linux publisher

## macOS-пакет

macOS workflow публикует self-contained Desktop для `osx-arm64` с apphost Local Node рядом, собирает нативный bundle `.app`, применяет ad hoc-подпись, проверяет bundle и создает загружаемый DMG

## Документация

```bash
cd Docs

```
