# Участие в разработке

Начните с issue или короткого design note, если изменение затрагивает архитектуру, постоянные данные, авторизацию или упаковку

## Рабочий процесс

1. Создайте отдельную ветку для задачи
2. Не затрагивайте посторонние пользовательские изменения
3. Добавьте тесты для измененного поведения
4. Обновите пользовательскую, техническую или API-документацию в той же задаче
5. Запустите нужные .NET-тесты и `pnpm build` в `Docs`
6. Запустите `python3 Scripts/license_headers.py --check` и проверьте workflow REUSE перед открытием pull request

## Проверка pull request

- поведение и компромиссы описаны обычным языком
- граница между Avalonia и Core остается понятной
- документация публичного API заполнена
- учетные данные, локальные пути, результаты сборки и кеши не добавлены
- документация описывает реализацию, а не планы

В отчете об ошибке укажите платформу, версию HyPrism, шаги воспроизведения, ожидаемый и фактический результат, а также подходящие логи
