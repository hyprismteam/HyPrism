# Тестирование

Запустите активные тесты из корня репозитория

```bash
dotnet test Tests/HyPrism.Core.Tests/HyPrism.Core.Tests.csproj
dotnet test Tests/HyPrism.LocalNode.Tests/HyPrism.LocalNode.Tests.csproj
dotnet test Tests/HyPrism.Desktop.Tests/HyPrism.Desktop.Tests.csproj
```

Тесты Core проверяют координацию запуска и работу профилей. Тесты протокола, постоянного состояния, сертификатов и процессов Local Node находятся в `HyPrism.LocalNode.Tests`. Их HTTPS-клиенты используют pinning созданного сертификата и отключают изменения системного доверия, поэтому запуск набора не добавляет временные центры сертификации в root store Windows и не показывает запросы доверия. Desktop-тесты используют Avalonia Headless для проверки локализации и важных состояний окна

Job `local-node-macos` из `.github/workflows/tests.yml` запускает session- и trust-тесты Local Node на `macos-15`, публикует apphost Desktop и Local Node для `osx-arm64` и выполняет реальный HTTPS-запрос после регистрации созданного сертификата в одноразовом System Keychain runner. Детерминированные тесты проверяют production-последовательность команд user Keychain, включая ограничение доверия именем хоста и ротацию сертификата. CI не может подтвердить интерактивный диалог безопасности пользователя или заменить финальный запуск с установленным клиентом Hytale на физическом Mac

## Границы тестов

- проверяйте доменное поведение через интерфейсы Core
- используйте временные каталоги для постоянного состояния
- не обращайтесь к реальной авторизации, игре или сторонним API в unit-тестах
- добавляйте регрессионный тест при исправлении воспроизводимой ошибки
- делайте render-тесты независимыми от системной темы

После изменения страниц, навигации или конфигурации Docusaurus запускайте сборку документации
