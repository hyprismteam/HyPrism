# Производительность Avalonia

Измеряйте UI при воспроизводимых размере окна, маршруте навигации, данных и рендерере. Headless-тесты проверяют структуру и состояние, но не частоту кадров системного композитора

## Компоновка и коллекции

Ограничивайте длинные списки через `Grid` и используйте виртуализацию. `StackPanel` вдоль оси прокрутки дает бесконечное ограничение и может отключить виртуализацию

```xml
<Grid RowDefinitions="Auto,*">
  <TextBlock Text="Items" />
  <ListBox Grid.Row="1" ItemsSource="{Binding Items}">
    <ListBox.ItemsPanel>
      <ItemsPanelTemplate>
        <VirtualizingStackPanel />
      </ItemsPanelTemplate>
    </ListBox.ItemsPanel>
  </ListBox>
</Grid>
```

Фрагмент предполагает модель со свойством `Items`. Для небольших ограниченных групп подходит `ItemsControl`; заменяйте коллекции пакетно и не отправляйте каждый элемент отдельным вызовом dispatcher

Используйте `IsVisible="False"`, если скрытое содержимое не должно участвовать в компоновке и обработке ввода. Прозрачное содержимое все еще может участвовать в обоих процессах

## Старт и фоновая работа

`DeferredContentControl` откладывает создание представления и сохраняет его после реализации. При обычном запуске разделы могут прогреваться под экраном загрузки. Тест начального дерева измеряет неинициализированное окно, а не полностью прогретое приложение

Сетевые данные и тяжелые преобразования готовятся вне dispatcher. Частые обновления прогресса объединяются до последнего значения, изображения статьи освобождаются при закрытии

## Анимация и рендеринг

Используйте общие элементы и `MotionDurations`. Непрерывная анимация вызывает `TopLevel.RequestAnimationFrame`, останавливается при скрытии или отсоединении и учитывает прошедшее время вместо фиксированной частоты кадров

Desktop ограничивает кэш ресурсов Skia до 256 МиБ и использует режим сборщика мусора с низкой задержкой. В Windows выбирается производительный адаптер рендеринга с программным резервным вариантом. Эти настройки окна независимы от выбора GPU для игры

Для сравнения режима композиции Windows в PowerShell

```powershell
$env:HYPRISM_WIN32_COMPOSITION = 'winui'
dotnet run --project Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
```

Поддерживаются `dxgi` по умолчанию, `winui` и `dcomp`. После диагностики удалите переменную

```powershell
Remove-Item Env:HYPRISM_WIN32_COMPOSITION
```

## Проверка регрессий

1. Отдельно воспроизведите запуск, навигацию, прокрутку или прогресс загрузки
2. Запишите время UI-потока, выделения памяти, число визуальных элементов и поведение кадров
3. Измените одну причину и повторите на тех же данных
4. Добавьте точную регрессионную проверку измеряемого поведения

Запустите существующие тесты Desktop

```bash
dotnet test Tests/HyPrism.Desktop.Tests/HyPrism.Desktop.Tests.csproj
```

`AvaloniaPerformanceTests` проверяет начальное дерево, отложенную реализацию, виртуализацию и пакетные уведомления коллекций. Render-тесты ожидают наблюдаемое итоговое состояние вместо предполагаемой длительности анимации
