# Local Node

Автономный режим запускает `HyPrism.LocalNode` как отдельный вспомогательный процесс на `https://h.localhost:8443`. Хост привязан к loopback, отклоняет неожиданные заголовки Host, ограничивает тела запросов 2 МБ и не требует отдельно развернутый `hytale-auth-server`

## Цепочка запуска

1. `GameLauncher` выбирает `Assets.zip` экземпляра и запускает Local Node до патча и запуска игры
2. Нода создает одну временную пару ключей Ed25519 для выбранного локального профиля
3. Лаунчер получает identity и session токены через `POST /v1/sessions`
4. `ClientPatcher` направляет известные префиксы сервисов Hytale на loopback authority
5. Игра получает ограниченное доверие к сертификату через `SSL_CERT_FILE` и Java trust store PKCS#12
6. DualAuth проверяет встроенный JWK и выполняет handshake с удаленным сервером без обращения сервера к loopback-ноде игрока
7. После запуска игры лаунчер передает владение lifetime Local Node PID игрового процесса
8. Нода продолжает работать при закрытии лаунчера и самостоятельно завершается после выхода игры

Патч клиента поддерживает обычные length-prefixed строки и Linux NativeAOT frozen strings, где последний символ граничит с метаданными runtime. Замена frozen string сохраняет этот байт метаданных. Патч может переключаться между сетевым и автономным endpoint, а перед патчем другого endpoint HyPrism восстанавливает стабильную исходную копию

## Группы endpoint

| Группа | Маршруты |
| --- | --- |
| Готовность и ключи | `/health`, `/.well-known/jwks.json`, `/jwks.json` |
| Сессии | `/v1/sessions`, `/game-session`, `/game-session/new`, `/game-session/child`, `/game-session/refresh`, `/game-session/authorize`, `/server-join/auth-grant`, `/server-join/auth-token`, `/game-session/exchange`, `/validate`, `/server/auto-auth` |
| Управление lifetime | `/v1/lifecycle/attach`, `/v1/lifecycle/stop` с уникальным секретом процесса лаунчера |
| Данные аккаунта | `/my-account/game-profile`, `/my-account/get-profiles`, `/my-account/get-launcher-data`, `/profile/uuid/{uuid}`, `/profile/username/{username}` |
| Аватары и косметика | `/my-account/skin`, `/my-account/cosmetics`, `/account-data/skin/{uuid}`, `/player-skins`, `/player-skins/active`, `/player-skins/{skinId}` |
| Совместимость | configs, live config, telemetry, empty-state social routes, настройки presence и пустой список серверов |

Authorization grant и access token содержат публичный встроенный JWK, но никогда не его приватное значение `d`. Access token копирует запрошенный отпечаток сертификата в `cnf.x5t#S256`. JWKS содержит только публичные ключи активных сессий

Запросы child-session и refresh выпускают новые пары токенов с существующим ключом профиля. В `/game-session/authorize` Bearer token подтверждает сессию игрока, а identity token в теле запроса указывает на целевой сервер. Это повторяет upstream handshake одиночной игры и не позволяет принять личность сервера за сессию игрока

Identity token, authorization grant и server access token передают активные данные персонажа в строковом claim `skin`, как в upstream-сервере. Встроенный сервер читает этот claim при создании игрока, а endpoint аккаунта и скинов продолжают обслуживать редактор в меню

`/my-account/cosmetics` повторяет форму ответа `sanasol/hytale-auth-server`. Нода читает каждую категорию редактора персонажа из `Assets.zip` активного экземпляра и возвращает ID всех установленных предметов как разблокированные. Небольшой upstream-каталог совместимости используется только тогда, когда архив отсутствует или поврежден

## Хранение и доверие

Локальные данные хранятся в каталоге `LocalNode` внутри каталога данных HyPrism

| Файл | Назначение |
| --- | --- |
| `accounts.json` | локальные профили, скины, активный скин и настройки presence |
| `h.localhost.pfx` | постоянный TLS-сертификат loopback и приватный ключ |
| `h.localhost.crt` | публичный сертификат PEM |
| `client-ca-bundle.pem` | набор CA для игрового процесса Unix |
| `client-trust.p12` | Java trust store для JVM встроенного сервера |
| `macos-trusted.crt` | копия сертификата, зарегистрированного в пользовательских trust settings macOS |
| `local-node.log` | изолированные события запуска, lifetime, статусы и время session-запросов, ошибки Local Node |
| `local-node.previous.log` | предыдущий изолированный лог после ротации по размеру |
| `unimplemented-requests.ndjson` | журнал method, path и имен query-параметров неизвестных запросов без заголовков, значений и тел |

TLS-сертификат заменяется, если он поврежден, выпущен для другого хоста или будет действовать менее семи дней. Windows добавляет публичный сертификат в root store текущего пользователя. Linux и macOS передают объединенный CA bundle игровому процессу для компонентов OpenSSL, а Java на каждой платформе получает отдельный trust store PKCS#12

При первом автономном запуске macOS просит пользователя разрешить доверие к сертификату в Apple user trust settings. Доверие ограничено политикой `ssl` и хостом `h.localhost`. HyPrism проверяет результат до запуска игры и удаляет прежнюю запись доверия при ротации сертификата. Отмена системного диалога останавливает автономный запуск с понятной ошибкой вместо ослабления проверки сертификатов

Провайдеры логирования ASP.NET отключены для вспомогательного процесса, поэтому диагностика запросов сервера не использует статический логгер HyPrism и его console stream. Лаунчер сообщает только о запуске процесса, готовности, привязке и исключительных ошибках управления, а подробные события ноды остаются в `local-node.log`. Для маршрутов авторизации записываются только method, path, response status и duration без заголовков, токенов и тел запросов

Встроенный хост автоматически получает каталог активного экземпляра игры. При отдельном запуске `HyPrism.LocalNode` передайте `--assets-path /absolute/path/to/Assets.zip`, чтобы открыть полный каталог установленной косметики

## Ограничения

Local Node является backend совместимости одного устройства, а не децентрализованной социальной сетью. Без отдельного слоя координации она не может дать глобально уникальные имена, общий граф друзей, presence между устройствами, invites, облачную синхронизацию косметики, публичный discovery и NAT traversal

Формы endpoint основаны на открытой поверхности совместимости `sanasol/hytale-auth-server`. Автоматические тесты покрывают локальную HTTPS-сессию, аккаунт, JWKS, обмен grant, привязку сертификата, хранение аватаров и переключение патча. End-to-end проверка каждой будущей проприетарной сборки клиента Hytale все еще требует совместимую установку клиента
