# Core contracts

`Bootstrapper.Initialize` registers the default implementations and returns an `IServiceProvider`. A host may add platform-specific registrations through its configuration callback

Desktop reads the launcher version generated from `HyPrism.Desktop.csproj` and configures the shared HTTP identity during startup. News, runtime provisioning, GitHub, and DualAuth requests use `HyPrism/<version>` without a separately maintained version constant

| Feature | Main contracts | Responsibility |
| --- | --- | --- |
| Configuration | `IConfigStore` | shared launcher and game configuration persistence |
| Progress | `IProgressReporter` | throttled progress and error events scoped to an instance operation |
| Versions | `IGameVersionCatalog`, `IVersionSource`, `IMirrorCatalog`, `IMirrorDiscovery` | version lists, source selection, mirror persistence and discovery, cache, and patches |
| Instances | `IInstanceRepository`, `IInstanceMigrator` | paths, metadata, persisted ordering, selection, import, migration, and `InstancesChanged` notifications |
| Downloads | `IFileDownloader`, `IPatchManager`, `IButlerClient` | transfer, file size checks, patching, and Butler |
| Runtime | `IRuntimeProvisioner` | cancellable JRE and Visual C++ prerequisite installation, runtime discovery, and compatibility checks |
| Launch | `IGameInstallationWorkflow`, `IGameLaunchCoordinator`, `IGameLauncher` | orchestration from a selected or explicitly addressed instance to process start; the coordinator raises `LaunchFailed` when an attempt ends without a running process |
| Process | `IGameProcessTracker` | persistent process tracking, typed lifecycle events, downtime reconciliation, and controlled per-instance exit |
| Console | `IGameConsoleService` | per-instance live output buffer with typed line events for the instance console |
| Mods | `IModManager` | search, install, import, enable, disable, delete, update checks, and changelog retrieval |
| Authentication | `IHytaleAuthenticator`, `IOAuthCallbackPageRenderer`, `GameSessionAuthenticator` | official sessions, OAuth challenges, host-rendered callback pages, and game tokens |
| Profiles | `IProfileManager`, `IProfileRepository`, `IUserIdentityProvider` | identity, persisted profile ordering, profile lifecycle, and `ProfilesChanged` notifications |
| Assets | `IAvatarCache`, `ISkinRepository` | avatar and skin data used by profiles and game launch |
| Platform | `IGpuProvider` | GPU detection required by cross-platform game launch |
| Presence | `IDiscordPresence` | host-provided launcher and game presence updates |

Contracts live beside their feature implementation. `Application/Ports` is reserved for capabilities supplied by the active host, currently `IDiscordPresence` and `IGpuProvider`

Prefer the narrowest contract required by a consumer. Avoid resolving dependencies from the container inside domain code

Interactive OAuth does not depend on a browser service in Core. The host passes an asynchronous URI launcher into the launch operation, and Core uses it only when an official account requires authorization. A host may register `IOAuthCallbackPageRenderer` to replace the minimal fallback HTML returned by the local callback listener

Long-running contracts place `CancellationToken` last. Installation forwards cancellation into runtime and Butler downloads, file writes, archive extraction, and process waits. Instance ZIP import and official-session lookup also observe cancellation through their asynchronous file and HTTP operations

Avalonia preferences are exposed by `IDesktopSettingsStore` in `HyPrism.Desktop`. Core components that require launch configuration consume `IConfigStore` directly

`IHytaleNewsClient`, `IGitHubClient`, and their implementations belong to Desktop features. News exposes only the official Hytale feed and structured articles, while GitHub metadata is used by the About page
