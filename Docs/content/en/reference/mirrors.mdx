# Mirrors

HyPrism supports the official Hytale source and optional JSON-defined mirrors added by the user

A mirror definition describes its identity, enabled state, priority, request headers, platform mappings, version list endpoint, full image endpoint, and optional differential patch endpoint

## Storage

Definitions are stored as `<id>.mirror.json` files in the `Mirrors` directory under the application data directory. `IMirrorCatalog` validates identifiers and schema shape before writing a definition

The regular Settings UI manages these files through Core and never edits JSON directly. Advanced setups can still provide a compatible definition manually

## Discovery and UI flow

`IMirrorDiscovery` inspects a public HTTPS endpoint and infers a candidate schema. Desktop validates the address, rejects duplicate endpoints, assigns a unique local identifier, saves the definition through `IMirrorCatalog`, and reloads the runtime sources

Plain HTTP is accepted only for loopback addresses used during local development

## Runtime selection

`IGameVersionCatalog` loads enabled mirror definitions, preloads source metadata, caches speed tests, and selects an available source. Enabling, disabling, adding, or removing a source reloads the runtime source list without restarting the launcher

The obsolete `PreferredMirror` configuration value is ignored because selection is automatic

## Security

- use HTTPS endpoints you trust
- never commit private authorization headers
- assume a mirror can provide hostile data
- keep integrity and extraction checks enabled
- custom mirrors do not change the user’s obligations under the Hytale EULA or local law

HyPrism does not ship preconfigured third-party game mirrors
