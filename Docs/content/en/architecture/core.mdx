# HyPrism.Core

`HyPrism.Core` owns behavior that must not depend on a specific UI toolkit

## Application and infrastructure

- `Application/Composition` builds the default dependency graph
- `Application/Progress` publishes throttled download progress and error events scoped to an instance operation, letting stage changes and completion always through
- `Application/Ports` contains only host-provided capabilities such as Discord presence and GPU discovery
- `Infrastructure` contains JSON configuration persistence, logging, and shared launcher utilities
- `Integrations/Hytale` contains protocol details required to communicate with official Hytale endpoints

## Game

- `Game/Versions` resolves official and mirror version metadata and caches source results
- `Game/Download` streams files, applies patch sequences, and reports progress
- `Game/Instances` owns instance metadata, paths, selection, import, deletion, and migrations, and raises `InstancesChanged` whenever the instance collection changes so hosts can subscribe instead of polling
- `Game/Launch` prepares Java, client endpoint redirection, the DualAuth Agent, environment variables, and the game process. Runtime downloads and installer waits observe operation cancellation, and official JRE archives with a published SHA-256 value are verified before extraction. Failed verification removes the downloaded archive on every supported platform. The process tracker raises typed started and exited lifecycle events carrying the instance identifier and exit code, reconciles processes that ended while the launcher was closed, and the launch coordinator raises `LaunchFailed` when an attempt ends without a running process
- `Game/Authentication` obtains connected game sessions or issues self-contained OmniAuth tokens through the Local Node
- `HyPrism.LocalNode` hosts the autonomous session, account, installed cosmetics catalog, configuration, and empty-state social compatibility surface
- `Game/Assets` manages avatar data required by profiles and game launch
- `Game/Mods` searches and installs CurseForge or local mods
- `Game/Patching` owns the Butler client used for differential updates
- `Game/Sources` implements official and JSON mirror sources, mirror discovery, and validated mirror persistence

## Accounts

`Accounts` is divided into authentication, profiles, identity, and skins. Contracts stay beside their implementation instead of being collected in a separate abstractions directory

Both the profile repository and the profile manager raise `ProfilesChanged` after creating, deleting, switching, reordering, or editing profiles, so hosts react to profile state through events instead of refreshing manually. On game process exit, the profile repository accumulates total play time and per-instance counters used to resolve the profile's most played instance

## Dependency rule

Core may expose host capabilities through interfaces, but it must not reference Avalonia or any presentation model

OAuth remains UI-neutral: Core creates the authorization URI and accepts a host callback for presenting it. Opening a browser is owned by the active application host. `IOAuthCallbackPageRenderer` lets that host brand the local callback response without adding presentation assets or Avalonia dependencies to Core

Core resolves profile directories but never opens a system file manager. Native file dialogs and system memory detection belong to `HyPrism.Desktop`

Game launch depends only on `IGpuProvider` and `GpuAdapterInfo`. Each host owns the concrete adapter discovery implementation

News parsing, GitHub metadata, and the Discord Rich Presence adapter belong to `HyPrism.Desktop`. Core only consumes `IDiscordPresence` as a host capability while reporting launcher and game activity

## Local Node

`HyPrism.Desktop` owns a `LocalNodeHost` process controller behind the Core `ILocalNodeService` contract. Autonomous launch starts the dedicated `HyPrism.LocalNode` executable before patching the client, then transfers lifetime ownership to the game PID through the loopback control plane

The host listens only on `https://127.0.0.1:8443`. The loopback IP literal keeps the client off DNS entirely, so VPN clients with a tunnel DNS interceptor cannot break the resolution of the Local Node endpoint. The patch budget of at most 16 characters lets `ClientPatcher` redirect session, account-data, telemetry, live-config, social, server-discovery, and socket-gateway prefixes to one loopback authority without growing the embedded domain segment

OmniAuth signing keys live only for the dedicated node process attached to the active game. The identity handoff includes the private Ed25519 JWK required by DualAuth, while JWKS, authorization grants, and access tokens expose only public key material. Account, skin, and presence preferences persist below the application data directory

The companion clears ASP.NET logging providers and writes its own bounded file log into the launcher's current `Logs/<launch-time>/` directory. Closing Desktop releases only launcher-side process handles, while the node continues monitoring the game and writing to that session directory until the game process exits
