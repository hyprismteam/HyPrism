# HyPrism.Desktop

`HyPrism.Desktop` is the active application host

## Composition

- `App.axaml` loads shared tokens, styles, and resources
- `Shell` contains the main window, native chrome, navigation, top-level application state, and the frame-synchronized startup loading transition
- `Features/Dashboard` contains the home view and its instance presentation model
- `SettingsViewModel` adapts `IDesktopSettingsStore` to the settings UI
- `DesktopSettingsStore` owns Avalonia preferences and persists them through Core configuration storage
- `ExternalUriLauncher` opens links in the system browser and preserves the absolute escaped URI when handing OAuth requests to the operating system
- `FilePicker` uses Avalonia's native `StorageProvider` instead of shelling out to platform utilities
- `SystemMemoryProvider` provides the memory limit shown by Java settings
- `GpuProvider` implements the Core GPU boundary with host platform tools
- `Features/News` retrieves official Hytale news and keeps parsed feed and article caches under `Cache/News`
- the news reader prepares view models away from the dispatcher, realizes controls in background-priority ranges, reveals the document only after the final range, and creates only the template selected by each content kind
- news image decoding runs after text presentation at background dispatcher priority, limits decode concurrency, and releases decoded bitmaps when the selected article closes
- `Features/About` provides repository metadata, contributors, commits, and avatars for the About page
- `Features/Settings` owns the adaptive settings UI and Desktop preferences
- `Features/Profiles` owns the instance-aligned adaptive profile cards, content view, and creation wizard while delegating ordering, storage, switching, and session persistence to Core account services
- `Controls/WizardHost` owns wizard lifecycle, active-step normalization, reveal playback, delayed cleanup, and navigation-pane coordination for instance, profile, and download-source flows
- `Controls/WizardScreenTransition` provides the lower-level phased overview-to-wizard and wizard-step transitions, including render-clock-driven step animation, active-step recovery after interruption, and anchor tracking limited to an open wizard
- `Controls/WizardRevealIcon` provides the common anchor, motion layer, and Lottie player so reveal icons load consistently without animating their layout position while a wizard opens or closes
- `Controls/AdaptiveMasterDetailHost` owns the shared wide and compact master-detail state, breakpoint, column placement, content sizing, and remembered detail intent while keeping layout synchronization immediate and user navigation animated
- `Controls/ReorderableListController` owns pointer capture, drag previews, and drop-index calculation for profile and instance lists
- `Platform` contains native URI, file picker, memory, and GPU adapters plus the shared persistent remote image cache
- `Integrations/Discord` implements the Core presence port and follows the Avalonia host lifetime
- custom controls handle rich news content, smooth scrolling, animated combo boxes, and reusable fading popups
- `.resx` files under `Localization` provide UI strings for every supported culture

## UI foundation

Reusable desktop presentation is split into two layers:

- `Styles/Tokens.axaml` defines surface, text, interaction, navigation selection, semantic status, toggle, and popup colors
- `Styles/Controls.axaml` defines the shared animated ComboBox, popup surface, ComboBox items, toggle switches, `SettingsRow`, wizard actions, and segmented controls

Feature views opt into reusable controls with `uiComboBox`, `uiPopupSurface`, `uiToggle`, `uiSettingsGroup`, `uiSettingsRow`, and `uiSegmentedControl` classes. Enabled buttons, selectors, toggles, and sliders receive the shared hand cursor while text input and resize surfaces keep their specialized cursors. `FadingPopup` owns opening, closing, light dismiss, keyboard dismiss, animation timing, and close retention for both ComboBox lists and feature menus. New interaction colors and animation timings belong in this foundation instead of feature-scoped styles

`MotionDurations` names shared animation timings by purpose. `RotatingVisual.IsActive` provides one render-clock-driven spinner behavior that starts and stops from binding state instead of feature-owned timers

The desktop project uses compiled bindings by default. View models expose state and commands while code-behind is limited to control behavior that depends on Avalonia input, layout, or animation primitives

External links and file dialogs stay in Desktop. URI presentation is passed to Core as an asynchronous callback only for interactive OAuth, while file selection is consumed directly by Desktop view models. Desktop also implements `IOAuthCallbackPageRenderer` with the HyPrism logo, launcher colors, responsive layout, result state, and close-window guidance localized from the current `IDesktopSettingsStore.Language` value

News and GitHub response models stay beside their Desktop features because they are presentation-facing data and are not part of game or account logic
