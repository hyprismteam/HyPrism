# Instances, profiles, and mods

The Core contains the working domain logic for all three areas. Native instance and profile managers are available, while advanced mod pages are still being completed

## Instances

The native instance manager presents local installations as a settings-style list with the same pane spacing, rounded category cards, hover animation, and responsive card sizing. Wide layouts highlight the instance open in the management workspace, while the compact list does not retain an active highlight before navigating into its content. Compact cards show the default grass block icon after the six-dot drag handle, and their borderless drag preview repeats the same icon and layout. The handle reorders cards and persists their order in `instances.json`. Opening a card changes only the instance shown in the management workspace and does not change the instance selected for Home or game launch. The neutral **New Instance** action below the list has no separator and creates a new installation by selecting a release channel and available version. The manager uses a two-column layout in wide windows and a stacked one-column layout when space is limited. With no instances, the list pane is removed so the create action has the full page

Selecting an instance opens its own content workspace. Wide layouts show the default grass block instance icon above one large centered segmented action and use equal spacing around the information group. The action launches an installed game or installs and launches a missing game, opens the instance directory, and deletes the instance after confirmation. While installation is active, the primary action expands to show the current stage, overall percentage, and a spinner while the delete segment contracts. Launch preparation uses the same layout with an elapsed timer. After the game starts, a running icon replaces the spinner, the label changes to **Running**, and the timer begins measuring the current play session. Hovering the active primary action slides its content to **Cancel**, changes its background to strong red, and uses white text. Progress and errors remain inside the action workflow because standalone progress cards and screen-edge activity cards are not used. Compact layouts place a small version of the icon to the left of the instance name in the top toolbar and apply the same animated states to its primary action. Its adjacent arrow opens an animated settings-style popup containing the folder and delete actions while idle. These actions target the open management instance without changing the Home selection. A compact 2 by 2 information group shows status, branch, version, and tracked play time without repeating the instance name. The management group uses Fluent asset icons for **Installed mods**, **Discover mods**, **Worlds**, **Console**, and **Logs**. Console and log destinations are ready for planned per-instance tracking, while installed mod search reads the selected instance manifest and files, catalog installs target that same instance, and the worlds screen reads directories from `UserData/Saves`

Cancellation becomes available only after the pointer leaves the newly activated action and enters it again, so the starting click cannot immediately expose or trigger **Cancel**. The spinner and running icon occupy the left action zone, progress or elapsed time occupies the matching right zone, and the status remains centered between them

Launch preparation runs outside the UI thread so navigation and action animations remain responsive while files, patches, authentication, and the game process are prepared. The active action uses equal fixed side zones, matching icon geometry, and tabular timer digits so entering the running state and changing seconds do not move its contents

Stopping a running game from the active action terminates its process tree and waits for the tracked process exit event. Closing the game itself uses the same event and immediately releases the action instead of retaining a disabled state while launch readiness is still waiting for output. The event also stops the session timer, records play time, and restores idle launcher presence even if an optional cleanup step fails

If HyPrism is reopened while a launched game is still running, its instance action restores the running state and can stop that same process. If the game ended while HyPrism was closed, the next startup reconciles the stored process record and retains play time and launch cleanup

Installation status is derived from the game files whenever an instance is opened and is not persisted in `instances.json`

The responsive structure matches Settings. Wide windows keep the instance list beside its workspace and use the phased transition when opening a content section. Compact windows show the instance list as the first page, slide an explicitly opened instance into the same space, and use the standard compact top toolbar and horizontal slide for nested content. Opening the creator from the compact list slides the prepared wizard directly into view, and cancelling slides it back to that list without briefly showing the first instance. Moving from a compact list to a wide window may display the first instance automatically, but returning to compact preserves the list until the user explicitly opens an instance. Content that was explicitly opened before or during the wide layout remains open when returning to compact. Settings categories follow the same intent-aware transition behavior

When no instances exist, the page starts with the first step of an instance wizard. Selecting **Select version** uses a phased transition that removes the first step before showing a configuration screen with a wrench icon, title, explanation, branch switch, and version picker. The branch switch uses a light gray sliding selection. The version picker shows a spinner only while uncached data is loading. Switching to a branch with fresh cached versions updates the picker immediately without another catalog request. Creating an instance does not download game files immediately. Select it and use the main action to download or launch it

Core can also migrate legacy layouts, change versions, import ZIP archives, and delete installations

## Profiles

Core supports offline and official profiles, stable profile identifiers, per-profile data, identity switching, avatar backups, skin recovery, and authentication session storage

The complete profile list is stored in `Profiles/profiles.json`. `config.json` contains only `SelectedProfileId`, so creating, selecting, renaming, and deleting a profile always changes the multi-profile store instead of a second launcher identity

Launching requires an existing selected profile with a valid name and UUID. HyPrism does not silently create an identity during launch

The **Profiles** destination uses the same responsive master-detail pattern, full-card interaction, transitions, and card styling as Instances. In a wide window, the saved-profile list stays beside the displayed profile. In a compact window, opening a profile or **Add** shows the content view and the back action returns to the list. Drag a card by its left handle to persist a new order. Open its three-dot menu to duplicate it or delete an inactive profile after confirmation

Opening a saved profile only displays its details. Use the primary **Select** action to change the launcher identity used for launch. Its icon and label animate into a white **Active** label over a saturated green background. The selected profile cannot be deleted, and its delete action contracts out of the wide action row while the compact primary action keeps its normal width. **Open Folder** opens the displayed profile rather than the selected profile, and **Copy UUID** copies the displayed identifier

Use **Add** below the final profile card to open the same animated full-content wizard transition as instance creation and choose an offline or official profile. The displayed profile remains mounted throughout the outgoing phase before the wizard enters. The wizard uses the Fluent profile asset, applies the same phased animation when moving forward to an account form or back to the account-type choice, and keeps the current step intact throughout its closing animation. In compact mode it returns to the list that opened it instead of showing the first profile. Offline names accept 3 to 16 English letters, digits, hyphens, and underscores. Official creation starts the local `/authorization-callback` handler before opening the Hytale sign-in flow in the system browser, preserves the escaped authorization URI, and validates the returned OAuth state. HyPrism saves each returned game profile, stores its session data in the corresponding profile folder, and selects the first returned profile

## Mods

Core integrates with CurseForge for search, categories, file resolution, installation, local file import, changelogs, and update checks scoped to an instance

Mods do not have a global navigation destination. Open an instance and use **Installed mods** to inspect its content or **Discover mods** to search and install new content. This keeps every mod operation attached to an explicit installation target
