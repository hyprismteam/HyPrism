# Instances, profiles, and mods

The Core contains the working domain logic for all three areas. The native instance manager is available, while profile and mod pages are still being completed

## Instances

The native instance manager presents local installations as a settings-style list with the same pane spacing, rounded category cards, hover animation, and responsive card sizing. Wide layouts highlight the instance open in the management workspace, while the compact list does not retain an active highlight before navigating into its content. Compact cards also show the default grass block icon after the six-dot drag handle. The handle reorders cards and persists their order in `instances.json`. Opening a card changes only the instance shown in the management workspace and does not change the instance selected for Home or game launch. The neutral **New Instance** action below the list has no separator and creates a new installation by selecting a release channel and available version. The manager uses a two-column layout in wide windows and a stacked one-column layout when space is limited. With no instances, the list pane is removed so the create action has the full page

Selecting an instance opens its own content workspace. Wide layouts show the default grass block instance icon above one large centered segmented action and use equal spacing around the information group. The action launches an installed game or installs and launches a missing game, opens the instance directory, and deletes the instance after confirmation. Compact layouts place a small version of the icon to the left of the instance name in the top toolbar and move the launch or install action to its right side. Its adjacent arrow opens an animated settings-style popup containing the folder and delete actions. These actions target the open management instance without changing the Home selection. A compact 2 by 2 information group shows status, branch, version, and tracked play time without repeating the instance name. The management group uses Fluent asset icons for **Installed mods**, **Discover mods**, **Worlds**, **Console**, and **Logs**. Console and log destinations are ready for planned per-instance tracking, while installed mod search reads the selected instance manifest and files, catalog installs target that same instance, and the worlds screen reads directories from `UserData/Saves`

Installation status is derived from the game files whenever an instance is opened and is not persisted in `instances.json`

The responsive structure matches Settings. Wide windows keep the instance list beside its workspace and use the phased transition when opening a content section. Compact windows show the instance list as the first page, slide the selected instance into the same space, and use the standard compact top toolbar and horizontal slide for nested content

When no instances exist, the page starts with the first step of an instance wizard. Selecting **Select version** uses a phased transition that removes the first step before showing a configuration screen with a wrench icon, title, explanation, branch switch, and version picker. The branch switch uses a light gray sliding selection. The version picker shows a spinner only while uncached data is loading. Switching to a branch with fresh cached versions updates the picker immediately without another catalog request. Creating an instance does not download game files immediately. Select it and use the main action to download or launch it

Core can also migrate legacy layouts, change versions, import ZIP archives, and delete installations

## Profiles

Core supports offline and official profiles, stable profile identifiers, per-profile data, identity switching, avatar backups, skin recovery, and authentication session storage

The complete profile list is stored in `Profiles/profiles.json`. `config.json` contains only `SelectedProfileId`, so creating, selecting, renaming, and deleting a profile always changes the multi-profile store instead of a second launcher identity

Launching requires an existing selected profile with a valid name and UUID. HyPrism does not silently create an identity during launch

## Mods

Core integrates with CurseForge for search, categories, file resolution, installation, local file import, changelogs, and update checks scoped to an instance

Mods do not have a global navigation destination. Open an instance and use **Installed mods** to inspect its content or **Discover mods** to search and install new content. This keeps every mod operation attached to an explicit installation target

The native profile page is still being built. Historical interaction behavior can be inspected in version control when it is useful
