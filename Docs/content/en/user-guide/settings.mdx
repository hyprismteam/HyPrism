# Settings

Settings use the same adaptive master-detail layout as the news reader. Wide windows keep categories beside their content and constrain the selected page to a centered readable column. Compact windows show one page at a time, use the available width, and support the Back button or Escape

## Categories

| Category | Purpose |
| --- | --- |
| General | language, music, launch behavior, announcements, and news visibility |
| Downloads | official and community download sources |
| Java | bundled or custom runtime, initial memory, maximum memory, and extra arguments |
| Appearance | background selection and interface personalization |
| Network | connected or autonomous authentication for local profiles |
| Graphics | preferred GPU for game launch |
| Variables | user-defined environment variables passed to the game process on every platform |
| Data | application and instance storage locations |
| About | project and license information |

The GPU selected on the **Graphics** page applies to launched games. The HyPrism interface separately requests the system high-performance GPU when hybrid graphics are available. Windows uses the DXGI high-performance adapter order, while Linux uses the desktop GPU preference and PRIME offload variables. Existing Linux PRIME variables are preserved, and Avalonia can still use software rendering if hardware initialization fails

The Java runtime choices use the same hover highlight as the settings navigation. Advanced JVM arguments are shown as individual rows in a table and saved as soon as a row is added or removed. **Add** opens the shared launcher overlay, whose decorative shoulders remain joined to the body outline at every supported width. While the overlay is open the scene outline drops its bottom edge, so the sheet merges with the window border the same way as the mod catalog preview. Quoted values remain a single argument. Java heap arguments such as `-Xms` and `-Xmx` are managed by the memory controls and are rejected by the argument editor

The **Variables** page passes user-defined environment variables to the game process on every platform. Variables are shown as individual rows in the same table style as JVM arguments and saved as soon as a row is added or removed. **Add** opens the same shared launcher overlay and accepts one or more space-separated `KEY=VALUE` pairs, quoted values keep their spaces, and each new line becomes a separate row. Invalid assignments are rejected with an inline message. User variables are applied after the launcher-managed GPU, authentication, and Java environment values, so the last assignment wins when a key repeats. The preset examples above the table follow the current operating system

## Data storage

The Data page combines game instance storage and launcher data in one **Launcher Files** group. Each location is shown as a readable local path with an icon action that opens it in the system file manager

A donut chart above the file locations shows total disk usage and groups occupied space into instance files, images, mods, news articles, logs, and other files. Its darker segments contain multiple filled Material Symbols Rounded icons that drift, appear, and dissolve independently across each storage category, while the responsive legend uses the same grouped statistic cells and internal dividers as instance and profile information. The percentage labels use Google Sans. Static chart layers are cached, particle paths are recalculated only for a new animation cycle, updates are limited to 60 frames per second, and animation pauses while the chart is hidden. The legend keeps size and percentage values aligned. Encoded files in the persistent image cache are counted as images, while parsed feed and article data under `Cache/News` is counted as news. Storage is measured in the background during launcher startup and the cached result is reused when the page is opened

The borderless path fields use the same background as an inactive switch. Use **Edit** to choose a new instance folder. The action expands over **Reset** and starts its spinner as soon as the system folder picker opens, then returns smoothly to its idle size if the picker is closed. After a folder is selected, the expanded action shows a spinner, the move status, and byte-based completion percentage when files need to be copied. A short minimum active interval lets the opening transition finish even when an empty folder is moved or the location is reset immediately. Moving the pointer away during the copy arms cancellation, so the next hover shows **Cancel** and a click stops the copy while keeping the current folder selected. **Reset** appears only after the default location has been changed and returns it to `Instances` inside the launcher data directory. HyPrism removes the previous folder only after the copy and location update succeed

Instance storage cannot be changed while a game is running. The current paths can still be opened during an active game session

## Local profile authentication

Connected mode requests a session from the configured authentication service and keeps its account-data integration available. Autonomous mode starts a dedicated Local Node process on `https://h.localhost:8443`, creates an ephemeral OmniAuth identity, and redirects the client service endpoints to that node

Local Node attaches to the game process after launch. Closing HyPrism does not interrupt an active autonomous game session, and the node exits automatically when the game closes. Its isolated diagnostics are stored beside the launcher and instance logs in the current `Logs/<launch-time>/` directory

Both modes use the DualAuth Agent for the embedded server. HyPrism no longer modifies `HytaleServer.jar`. Installations left by an older release are restored from their backup before launch

The Local Node persists profiles, saved skins, and presence preferences on the device. It unlocks all character creator items found in the active instance's `Assets.zip`, while cosmetic choices remain local. Centralized friends, parties, invites, global presence, cloud cosmetic synchronization, and server discovery return compatible empty states because there is no shared backend. Direct friend joins still depend on a reachable host through LAN, UPnP, IPv6, port forwarding, or a VPN such as Tailscale

## Download sources

The Downloads page shows the official Hytale source and community mirrors in one table under **Download sources**. Its columns show the endpoint link, source type, current availability, and enabled state. Availability starts with a continuously rotating spinner that smoothly changes when the background probe finishes. A check means the source is available, a cross means it is unavailable, and a yellow-orange warning symbol means the mirror responds but exposes no release or pre-release versions for the current operating system and CPU architecture. When any profile has a valid official Hytale session, HyPrism checks the official source through its authenticated patches API and verifies that a download exists for the current platform. Source checks run on the first visit and their results remain in the table when switching settings categories or clicking the active category again. Changing the source list or enabling a source starts the relevant checks again. HyPrism continues measuring source latency for automatic source selection without displaying ping in the table

Selecting **Add** opens a wizard with a load-balancer reveal animation that initializes before the first visible frame and plays once at `2x` speed on every opening. Its light housing preserves the dark left indicator circle and status dots. The same final reveal frame remains visible on every step without restarting the animation. When a step changes the centered content height, the icon starts moving with the outgoing step and settles with the incoming step without being clipped. The first step lets you enter a public HTTPS address for automatic format detection or paste a complete `.mirror.json` definition manually. HyPrism validates either result before saving the source

The reveal icon appears at the first step's settled position and does not travel vertically while the wizard itself opens or closes. The active step remains visible throughout the closing fade and is cleared only after the overview returns

The download-source wizard uses separate rounded actions with a 10 px gap. **Back** and **Cancel** remain transparent secondary actions, while **Add source** is the wider white primary action

Each user-provided source can be enabled or disabled from the table. Its three-dot action menu contains source-specific actions, including removal with confirmation. HyPrism prioritizes the official download source and automatically selects the fastest added user mirror when the official source is unavailable

Only add sources you trust. Automatic mode only requests the public address, while manual JSON mode accepts the complete source definition, including optional custom headers

The About page shows the installed launcher version, the latest commit in `main`, project and community links, the core team, an adaptive row of recent contributors, the source-code license, the Hytale EULA, visual credits, and the disclaimer. Visual credits separate illustrations provided by Icons8 from animated media provided by Lordicon, with the required Lordicon link on its row. A subdued footer links to the official Avalonia UI and .NET websites, while its heading follows the selected interface language

Settings are written through `IDesktopSettingsStore` and persisted by `IConfigStore`
