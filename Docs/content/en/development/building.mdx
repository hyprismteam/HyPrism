# Building

## Requirements

- .NET 10 SDK
- Git
- Node.js 22 and pnpm only when working on the documentation

## Native launcher

```bash
dotnet restore HyPrism.sln
dotnet build Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
dotnet run --project Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
```

## Entire solution

```bash
dotnet build HyPrism.sln
```

The solution contains `HyPrism.Core`, `HyPrism.Desktop`, `HyPrism.LocalNode`, and their test projects

## Local publishing

Publish the native desktop host directly with the .NET SDK:

```bash
dotnet publish Sources/HyPrism.Desktop/HyPrism.Desktop.csproj \
  --configuration Release \
  --runtime linux-x64 \
  --self-contained true \
  --output dist/hyprism-linux-x64
```

Replace `linux-x64` with the target runtime identifier. The obsolete Electron packaging script is not part of the Avalonia release path

## GitHub Actions

`.github/workflows/ci.yml` is the push and pull request entry point. It calls the independent test workflow and the build dispatcher. `.github/workflows/build.yml` only selects platforms, while `build-linux.yml`, `build-windows.yml`, and `build-macos.yml` own their platform packaging

The current CI artifacts are a self-contained Linux x64 `tar.xz`, a self-contained Windows x64 ZIP, and a macOS ARM64 DMG. Release builds reuse the same platform workflows and pass the release version into artifact names

## macOS package

The macOS workflow publishes the self-contained `osx-arm64` Desktop application with the Local Node apphost beside it, builds a native `.app` bundle, applies an ad hoc signature, verifies the bundle, and creates the uploaded DMG

## Documentation

```bash
cd Docs
pnpm install --frozen-lockfile
pnpm build
```

The static site is written to `Docs/out`
