# Building

## Requirements

- .NET 10 SDK
- Git
- Node.js 22 and pnpm only when working on the documentation

## Native launcher

```bash
dotnet restore HyPrism.sln
dotnet build Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
dotnet run --project Sources/HyPrism.Desktop/HyPrism.Desktop.csproj
```

## Entire solution

```bash
dotnet build HyPrism.sln
```

The solution contains `HyPrism.Core`, `HyPrism.Desktop`, `HyPrism.LocalNode`, and their test projects

## Local publishing

The platform dispatcher is `Scripts/publish.sh`. On Linux it creates `deb`, `rpm`, AppImage, Flatpak bundle, and `tar.xz` from one self-contained Desktop publish output. Install `rpm`, Flatpak, Flatpak Builder, and appimagetool first, then run:

```bash
./Scripts/publish.sh all --version 1.2.3 --output dist
```

Use a specific Linux target such as `deb`, `rpm`, `appimage`, `flatpak`, or `tar` to build only that package. On macOS, `./Scripts/publish.sh dmg` creates the DMG. On Windows, run `bash Scripts/publish.sh all` in Git Bash to create ZIP, MSI, and EXE installer. All platform workflows call this dispatcher

## GitHub Actions

`.github/workflows/ci.yml` is the push and pull request entry point. It calls the independent test workflow and the build dispatcher. `.github/workflows/build.yml` only selects platforms, while `build-linux.yml`, `build-windows.yml`, and `build-macos.yml` own their platform packaging

The current CI artifacts are Linux x64 `deb`, `rpm`, AppImage, Flatpak bundle, and `tar.xz`, Windows x64 portable ZIP, MSI, and EXE installer, and a macOS ARM64 DMG. Release builds reuse the same platform workflows and pass the release version into artifact names

## macOS package

The macOS workflow publishes the self-contained `osx-arm64` Desktop application with the Local Node apphost beside it, builds a native `.app` bundle, applies an ad hoc signature, verifies the bundle, and creates the uploaded DMG

## Documentation

```bash
cd Docs
pnpm install --frozen-lockfile
pnpm build
```

The static site is written to `Docs/out`
