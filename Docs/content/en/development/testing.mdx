# Testing

Run all active tests from the repository root

```bash
dotnet test Tests/HyPrism.Core.Tests/HyPrism.Core.Tests.csproj
dotnet test Tests/HyPrism.LocalNode.Tests/HyPrism.LocalNode.Tests.csproj
dotnet test Tests/HyPrism.Desktop.Tests/HyPrism.Desktop.Tests.csproj
```

Core tests cover launch coordination and profile behavior. Local Node protocol, persistence, certificate, and process tests live in `HyPrism.LocalNode.Tests`. Their HTTPS clients pin the generated certificate and disable platform trust changes, so running the suite does not add temporary certificate authorities to the Windows root store or show trust prompts. Desktop tests use Avalonia headless rendering to verify localization and important window states

The `local-node-macos` job in `.github/workflows/tests.yml` runs Local Node session and trust tests on `macos-15`, publishes the `osx-arm64` Desktop and Local Node apphosts, and requests the Local Node `/health` endpoint after registering the generated `hyprism-local-ca.crt` root certificate in the runner's disposable System Keychain. The smoke test verifies the `h.localhost` server certificate issued by that root and checks that Local Node reports the `ready` status, expected server name, and HTTPS issuer. Deterministic tests verify the production user-Keychain command sequence, including hostname verification and certificate rotation. CI cannot approve the interactive user security dialog or replace a final launch with an installed Hytale client on a physical Mac

## Test boundaries

- test domain behavior against Core interfaces
- use temporary directories for persistent state
- do not call live authentication, game, or third-party endpoints in unit tests
- add a regression test when fixing a reproducible bug
- keep render tests deterministic and independent of the machine theme

Run the documentation build after changing any page, navigation metadata, or Docusaurus configuration
