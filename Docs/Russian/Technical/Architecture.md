# Архитектура

## Статус миграции на Avalonia

HyPrism переносится с Electron.NET на нативный desktop-host на Avalonia 12.
На время перехода доступны оба хоста:

```
HyPrism.Core       общие модели и сервисы .NET 10 (без Electron)
       ↑                              ↑
HyPrism.Desktop                 HyPrism.Launcher
Avalonia 12 + MVVM              Electron.NET + React + IPC
```

`HyPrism.Core` теперь физически содержит модели лаунчера, bootstrapper регистрации зависимостей
и платформонезависимые сервисы App, Infrastructure, Integration, Game и User.
`HyPrism.Launcher` ссылается на эту сборку и содержит только legacy Electron-host,
IPC-транспорт/контракты и Electron-адаптер буфера обмена. `HyPrism.Desktop` напрямую
ссылается на ту же Core-сборку, поэтому общий код компилируется ровно один раз.

Нативный shell использует compiled bindings Avalonia, `CommunityToolkit.Mvvm`,
существующие JSON-локализации и локально встроенный Google Sans. Уже подключены
реальные данные профиля и инстансов, запуск/установка, прогресс и состояние игры,
а также нативная лента новостей на базе `INewsService`.
Нативный раздел настроек также работает через общий сервис; Instances, Mods и Profiles пока остаются заглушками.
Визуальная основа использует фиксированный белый акцент и rounded Material Symbols,
хранящиеся напрямую как AXAML-геометрии weight 400. Навигация плавно переключается
между outline/filled-контурами пакета без Fluent hover/press-эффектов. Для собственного
chrome окна заданы явные нативные зоны перемещения и изменения размера с соответствующими курсорами.

Avalonia Dashboard вынесен в отдельный `DashboardView`, а orchestration запуска остаётся в
`MainWindowViewModel`. Вместо дублирующих карточек Instances, Mods и News страница показывает
выбранный инстанс и одно контекстное действие поверх фонового изображения. Активность скачивания
встроена в launch-блок, а вычисляемое состояние оставляет общую карточку активности для других
routes. При ширине меньше 900 px полоса быстрого выбора из трёх инстансов скрывается; выбор элемента
сначала обновляет `IInstanceService`, после чего пересобирается presentation state.

Нативный раздел «Новости» запрашивает у общего сервиса только официальные
публикации Hytale; релизы GitHub на этой странице не используются. Лента сначала показывает двенадцать
публикаций и подгружает их по восемь до лимита сервиса.
При ширине контентной области меньше 1180 px Avalonia `Carousel` и горизонтальный `PageSlide` с cubic easing плавно переключают
ленту и reader. Начиная с 1180 px страница становится master/detail-сеткой с тонированной поверхностью
ленты фиксированной ширины 420 px слева и прокручиваемой статьёй справа. Сам цвет поверхности разделяет
колонки; строки ленты имеют плавную hover/selected-заливку, но не имеют обводки, постоянной карточной заливки, заголовка секции, стрелок или бейджей Hytale. Compact-toolbar получает offset статьи из `SmoothScrollViewer`, всегда совпадает с ограниченной шириной и горизонтальными отступами hero и проявляет увеличенный точно центрированный заголовок после ухода с верхней позиции, не перемещая actions. В wide-reader нет «Назад», а external action находится внутри hero над заголовком. Обе кнопки остаются прозрачными и без обводки во всех pointer-состояниях.
Обложки загружаются асинхронно, а ширина текста
статьи ограничивается для удобного чтения.
`NewsService` разбирает серверный HTML Hytale через AngleSharp вместо регулярных выражений.
Для ленты выполняется один запрос, полный материал загружается только по требованию и преобразуется в безопасное дерево форматирования (абзацы,
заголовки, ссылки, блочные и inline-изображения, цитаты, сворачиваемые секции, иерархические списки, выделение и код).
Нативные модели списков сохраняют вложенные нумерованные и маркированные уровни, не объединяя дочерний
список с родительской строкой. Интерактивная область ссылки вычисляется по каждому отрисованному диапазону
текста, включая перенесённые строки. Обёрнутые сайтом
в абзацы или теги форматирования блочные медиа нормализуются в отдельные изображения. Классы Hytale
`emote` и `emote-sticker` остаются inline-узлами размером 1,5 em и 4 em соответственно. Абзац,
начинающийся со стикера, компонуется как строка со стикером и короткой репликой, после которой
продолжение занимает всю ширину без наложения строк. Avalonia отображает это дерево без исполнения
удалённого HTML или JavaScript. Служебные пробелы вокруг абзацев в пунктах списка отбрасываются, чтобы интервалы были одинаковыми. В шапке статьи автор, тип публикации и дата собраны в одну строку, а общее SEO-описание сайта не попадает в тело. Очищенные inline-ссылки со схемами `http` и `https`, как и явная кнопка
перехода к оригиналу, используют platform browser service и открываются в системном браузере. `NewsRichTextBlock` создаёт inline-код как компактный скруглённый chip через `InlineUIContainer`, сохраняя позиции text layout для hit testing соседних ссылок. Дочерний текст использует явную компактную высоту строки и не наследует метрику абзаца, поэтому chip больше не увеличивает и не перекрывает соседние строки при переносе. Этот chip и отдельные блоки кода используют встроенный JetBrains Mono; полный блок получает собственную тёмную поверхность с отступами и скруглением. Селекторы темы скрывают Fluent template parts `PART_LineUpButton` и `PART_LineDownButton` у обоих news-scrollviewer, не затрагивая перетаскивание ползунка, wheel input и autoscroll.
Разбор AngleSharp, построение article ViewModel и bitmap decoding выполняются вне UI-dispatcher; лента хранится 30 минут, а article tree семь дней в `Cache/News`. In-flight task объединяет повторные URL-запросы, а повторный выбор активной строки игнорируется. Skeleton появляется с задержкой, достаточной для быстрых cache-hit, и не может просвечивать через непрозрачную готовую статью. Готовые ViewModel и bitmap переиспользуются. При compact-выборе лёгкое состояние входящего reader публикуется до смены индекса `Carousel`; создание rich-блоков и загрузка изображений ждут завершения slide, после чего маленькие пакеты отдают compositor полный кадр между добавлениями. Когда первая пачка текста готова, FadeIn применяется только к телу ниже hero; toolbar и hero остаются неподвижными. Закрытые details не предоставляют дочерний ItemsSource до раскрытия и не создают скрытое дерево контролов. Back сохраняет исходящую статью до конца slide. При wide-выборе старый host скрывается без анимации; новая hero-картинка и gradient-mask сначала отрисовываются вместе, после чего выполняется только короткий fade-in. Это исключает двойное мигание и первый кадр без затемнения. `SmoothScrollViewer` плавно приближается к wheel-target и интерполирует скорость middle-click autoscroll вместо движения прямо из pointer event; нативный курсор выбирается между четырёхсторонним, верхним и нижним по целевому направлению.

Нативный Settings route повторяет master/detail-структуру News: выше собственного compact-breakpoint используется узкая лента разделов на `StrokeBrush` и независимая контентная область, ниже — обрезанный cubic slide между полным списком разделов и выбранным содержимым. Compact-строки показывают локализованные описания, но визуально подавляют сохранённый выбор раздела. Видимость reader хранится отдельно, поэтому переход через breakpoint из открытого wide-content сохраняет страницу. Один раздел может содержать несколько смысловых категорий. У каждой категории одна обрезанная фоновая карточка с полноразмерными строками параметров; строки разделены от края до края цветом основной поверхности приложения, а компактный заголовок стоит непосредственно над каждой карточкой в обоих layout-режимах. Compact-toolbar называет выбранный раздел, а не заменяет заголовки категорий. Compact-reader возвращается явной кнопкой «Назад». Существующие switch- и select-параметры связаны напрямую с `ISettingsService`, текстовые поля сохраняются явными командами. Смена языка обновляет принадлежащий Desktop ResX-сервис `LocalizationService`, CultureInfo, подписи, тип аккаунта и даты без пересоздания окна или settings ViewModel. Подписи существующих selector обновляются на месте, поэтому Avalonia binding не воспринимает обновление локализации как новый выбор и не записывает язык повторно. Core только сохраняет нормализованный языковой тег и не содержит каталог локалей, поиск ресурсов, смену культуры или уведомления UI.
Java-раздел сохраняет списочную структуру выбора runtime из legacy-интерфейса, но полностью отрисовывается нативными контролами Avalonia. Связанные ползунки `-Xmx` и `-Xms` записывают нормализованные значения с шагом 256 МБ через Core-класс `JvmArgumentBuilder`: Core отвечает за чтение, удаление и замену heap-аргументов, а Desktop — за лимит физической памяти, представление и проверку пути. Управляемые launcher-ом heap-флаги удаляются из пользовательского редактора расширенных аргументов и добавляются обратно только при сохранении. UI не создаёт и не предлагает профиль сборщика мусора.
Selector настроек использует `FadingComboBox`: логическое состояние открытия отделено от видимости popup, поэтому popup остаётся в visual tree на время анимации закрытия. Языковые варианты загружают 3:2 bitmap-флаги из `Assets/Flags`; в сборку входят только 13 регионов, представленных каталогом локалей.

`IGameLaunchCoordinator` — первая транспортно-независимая точка входа. Её вызывают
и Electron-канал `hyprism:game:launch`, и Avalonia ViewModel, поэтому orchestration
запуска больше не находится внутри IPC-адаптера.

## Обзор

HyPrism следует архитектурному паттерну **Console + IPC + React SPA**:

```
┌─────────────────────────────────────────────────────┐
│  Консольное приложение .NET  (Program.cs)           │
│  ├── HyPrism.Core (модели, DI, сервисы лаунчера)    │
│  └── IpcService.cs (Electron IPC-адаптер)            │
│         ↕ Сокетный мост Electron.NET                │
│  ┌─────────────────────────────────────────────┐    │
│  │  Electron Main Process                      │    │
│  │  └── BrowserWindow (без рамки)              │    │
│  │       └── preload.js (contextBridge)        │    │
│  │            ↕ ipcRenderer                    │    │
│  │       ┌─────────────────────────────┐       │    │
│  │       │  React SPA                  │       │    │
│  │       │  ├── App.tsx (маршрутизация)│       │    │
│  │       │  ├── pages/ (представления) │       │    │
│  │       │  ├── components/ (общие)    │       │    │
│  │       │  └── lib/ipc.ts (генерир.)  │       │    │
│  │       └─────────────────────────────┘       │    │
│  └─────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

## Процесс запуска

1. `Program.Main()` инициализирует логгер Serilog
2. Устанавливает `ElectronLogInterceptor` на `Console.Out`/`Console.Error`
3. `Bootstrapper.Initialize()` создаёт DI-контейнер
4. `ElectronNetRuntime.RuntimeController.Start()` создаёт процесс Electron
5. `ElectronBootstrap()` создаёт безрамочный `BrowserWindow`, загружающий `file://wwwroot/index.html`
6. `IpcService.RegisterAll()` регистрирует все обработчики IPC-каналов
7. React SPA монтируется, получает данные через типизированные IPC-вызовы

## Модель коммуникации

Вся коммуникация между фронтендом и бэкендом использует **именованные IPC-каналы**:

```
Именование каналов: hyprism:{домен}:{действие}
Примеры:            hyprism:game:launch
                    hyprism:settings:get
                    hyprism:i18n:set
```

### Типы каналов

| Тип | Направление | Паттерн |
|-----|-------------|---------|
| **send** | React → .NET (без ожидания ответа) | `send(channel, data)` |
| **invoke** | React → .NET → React (запрос/ответ) | `invoke(channel, data)` → ожидает `:reply` |
| **event** | .NET → React (push) | `on(channel, callback)` |

### Модель безопасности

- `contextIsolation: true` — рендерер не имеет доступа к Node.js
- `nodeIntegration: false` — нет `require()` в рендерере
- `preload.js` предоставляет только `window.electron.ipcRenderer` через `contextBridge`

## Сокетный мост IPC

IPC-мост использует HTTP-сокет для коммуникации .NET ↔ Electron.

### Совместимость с VPN (Windows)

В Windows сокет привязывается к `0.0.0.0` вместо `127.0.0.1` для обхода перехвата VPN.

**Безопасность**: Все подключения фильтруются — принимаются только loopback-адреса:
- `127.0.0.1` (IPv4 loopback)
- `::1` (IPv6 loopback)
- `::ffff:127.0.0.1` (IPv6-mapped IPv4)

**Отключить**: Установите `HYPRISM_VPN_COMPAT=0` для принудительной привязки к `127.0.0.1`.

### Реализация

Сокетный мост патчится в `.electron/custom_main.js` до инициализации Electron.NET:

```javascript
// Windows по умолчанию использует 0.0.0.0, другие — 127.0.0.1
const vpnCompatMode = vpnCompatEnv === '1' || (isWindows && vpnCompatEnv !== '0');

// Фильтрация соединений
if (!isLoopback) {
    socket.destroy();  // Отклонить не-loopback
}
```

## Внедрение зависимостей

Общие сервисы регистрируются как singleton в `Sources/HyPrism.Core/Bootstrapper.cs`.
Каждый host может добавить собственные адаптеры перед построением service provider:

```csharp
var provider = Bootstrapper.Initialize(services =>
{
    services.AddSingleton<ClipboardService>();
    services.AddSingleton<IpcService>();
});
```

Electron-host добавляет `IpcService` и свою реализацию буфера обмена; Core от них не зависит.
`IpcService` работает с общими контрактами вроде `IModService`, а не обращается к internal-реализациям Core.

## Перехват логов

Electron.NET выводит неструктурированные сообщения в stdout/stderr (например, `[StartCore]:`, `|| ...`). HyPrism перехватывает их через `ElectronLogInterceptor` (кастомный `TextWriter`, установленный на `Console.Out`/`Console.Error`) и направляет их через структурированный `Logger`:

- Сообщения фреймворка → `Logger.Info("Electron", ...)`
- Отладочные сообщения (`[StartCore]`, `BridgeConnector`) → `Logger.Debug("Electron", ...)`
- Паттерны ошибок (`ERROR:`, `crash`) → `Logger.Warning("Electron", ...)`
- Шумовые паттерны (`GetVSyncParametersIfAvailable`) → подавляются
